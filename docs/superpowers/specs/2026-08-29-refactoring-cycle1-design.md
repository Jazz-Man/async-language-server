# Refactoring Cycle 1 — error-model compliance — design

**Date:** 2026-08-29
**Status:** approved design, pre-implementation
**Inputs:** technical review `docs/superpowers/reviews/2026-08-29-technical-review.md` (findings register + ranked backlog) and the project rules `.claude/rules/{error-handling,tech,product}.md`
**Branch:** `feature/abstraction`

## Goal

Bring the crate's error handling into compliance with `.claude/rules/error-handling.md` and make the verification battery green again (clippy is red today). Every behavior fix is owner-approved in this spec and covered by a test.

## Decisions

- **D1 — two-cycle program.** The 12-item review backlog splits by theme. Cycle 1 (this spec): C1 + everything `error-handling.md` normatively requires. Cycle 2 (separate brainstorm later): hygiene and docs (rest of M5 lint allows, M2 leftovers if any, I9 README, M8 wording). Backlog item 11 (I2, resolve-method conversion) stays with the parked symbols cycle.
- **D2 — hard break on `ServerError`.** `Unknown(String)`, `ServerError::unknown()`, and the string `From` impls (`From<String>`, `From<&String>`, `From<&str>`) are removed, not deprecated alongside a new form. Every call site is rewritten to a typed variant or a boxed error. The commit message flags the breaking change (product.md: fork maintainers read commit messages).
- **D3 — C1 is fixed at the root.** The three `unused_async` sites are fixed mechanically AND the crate-internal mask (`#![allow(clippy::unused_async)]` in `server_trait.rs`) is removed by making `method_not_implemented` a plain function returning `std::future::ready(...)`. The other three module allows in that file are Cycle 2.
- **D4 — `#[non_exhaustive]` lands now**, folded into M2's territory: the enum is being broken anyway, so the attribute costs nothing and removes a second breaking touch later.
- **D5 — M7 is dropped** (Io-kind → specific LSP code mapping): no demonstrated need; YAGNI.
- **D6 — error module organization.** All error definitions live exclusively in one module. The module is renamed `src/result.rs` → `src/error.rs` (Rust convention: one primary error type, singular) — internal only; the public path `async_language_server::server::{ServerError, ServerResult, ServerErrorCode}` is unchanged. New variants are added to this module and nowhere else. A per-error-type file split (PHP/TS style) is rejected: enum variants cannot live in separate files, and one-type-per-file would recreate the per-module error hierarchy the rule deliberately rejects at this crate's size.
- **D7 — the "kilometer file" problem is registered, not solved here.** `server_state.rs` (~800 lines), `server_with_state.rs` (~890), `requests.rs` (~930) mix logic and inline tests; their size is logic + tests, not error definitions. A file-organization pass is a candidate for a later cycle, out of Cycle 1's scope.

## Design

### 1. Scope and success criteria

**In:** C1 (clippy-green at the root), error-model hard break (I1 + M1 + M3 + M4), walker resilience (I4), encoding negotiation without panic (I3), `didChange` fallback (I6), tracing on `Document::query` and fire-and-forget client requests (I5 + I7).

**Out:** everything listed in D1's Cycle 2, I2 (symbols), M7 (D5), file-organization pass (D7).

**Success:** the full battery is green in all three feature configurations, clippy included; `.claude/rules/error-handling.md` is satisfied for every path touched; each behavior fix has a test; the breaking change is named in the commit message.

### 2. The new `ServerError` (`src/error.rs`)

```rust
#[derive(Debug, Error)]
#[non_exhaustive]
pub enum ServerError {
    #[error("failed to connect to port {port}")]
    TcpConnect {
        port: u16,
        #[source]
        error: std::io::Error,
    },
    #[error("invalid file path '{path}'")]
    InvalidFilePath { path: PathBuf },
    #[error("json-rpc error {code}: {message}")]
    Rpc {
        code: ServerErrorCode,
        message: String,
    },
    #[error("{0}")]
    Lsp(#[from] async_lsp::Error),
    #[error("{0}")]
    Io(#[from] std::io::Error),
    #[error("{0}")]
    Other(#[from] BoxDynError),
}
```

- Removed: `Unknown(String)`, `ServerError::unknown()`, `From<String>`, `From<&String>`, `From<&str>`. `From<BoxDynError>` is generated by `#[from]` on `Other`.
- All Display messages are lowercase with discriminating values; `Rpc` shows code and message (M4).
- `From<ServerError> for ResponseError`: `Rpc` maps to its own code; every other variant maps to `INTERNAL_ERROR` with `to_string()` (each `Display` surfaces the inner error's message). The `UNKNOWN_ERROR_CODE` branch disappears with `Unknown`.
- The module doc/doctest is rewritten for the new shapes.
- Call-site rewrites: `transport.rs` constructs `TcpConnect { port, error }`; `workspace_walker.rs` `path_to_url` constructs `InvalidFilePath`; its entry-error propagation dissolves into skip-and-trace (§3).

### 3. Behavior fixes

- **Walker (I4):** `WorkspaceWalker::files()` no longer aborts on a failing entry. An unreadable entry is skipped with a `tracing::warn!` (feature-gated) that includes the error value; the scan continues. Without the `tracing` feature the skip still happens — the behavior is the skip, the trace is observability.
- **Encoding (I3):** new `Encoding::try_from_lsp(&PositionEncodingKind) -> Option<Encoding>`. The `initialize` negotiation maps client-advertised encodings through it with `filter_map`; unknown kinds are ignored as if the client had not advertised them. `from_lsp` remains for internal known-kind conversion (documented panic), and no external input reaches its panic branch anymore.
- **`didChange` fallback (I6):** when incremental application fails and the disk re-read also fails, the document stays tracked with its last-known text (possibly partially edited) plus a `tracing::warn!` — instead of being silently removed. Rationale: corrupt-but-present beats absent for handlers, while the editor still considers the file open. The successful-read path (reload from disk) keeps its semantics — the only recovery from partially applied edits under the synchronous-handler constraint — and gains a comment documenting the unsaved-changes hazard.

### 4. Tracing additions (I5 + I7)

- `Document::query`: when a grammar exists but `Query::new` fails, emit `#[cfg(feature = "tracing")] tracing::warn!` with the query string and the error value (house pattern). A missing grammar remains a silent `None` — that is configuration, not failure.
- Fire-and-forget client requests in `workspace_diagnostics.rs` (capability registration, diagnostics refresh): replace `let _ =` with a result match that logs the error value under the `tracing` feature.
- Both are observability only; no behavior change, no dedicated tests beyond existing coverage staying green.

### 5. C1 mechanics (first task of the plan)

- `method_not_implemented` becomes a plain `fn` returning `std::future::ready(Err(...))`; trait method signatures are untouched (they are already `fn … -> impl Future …`, not `async fn`).
- The three linting sites drop `async` and return `std::future::ready(Ok(...))`: `examples/minimal.rs`, `examples/tree_sitter.rs`, and the oneshot test server.
- `#![allow(clippy::unused_async)]` is removed from `src/server_trait.rs`; the other three module allows stay for Cycle 2.

### 6. Tests and verification

- `error.rs` unit tests: `TcpConnect`'s `source()` is the inner `io::Error`; `Other` preserves its boxed source; `From<ServerError> for ResponseError` maps `Rpc` to its code and `Io`/`Lsp`/`Other` to `INTERNAL_ERROR`; the doctest pins the new Display strings.
- Walker: a temp workspace containing one unreadable entry (chmod `000`) and one readable file — the readable file is still returned, the scan does not fail.
- Encoding: `initialize` with a client advertising an unknown encoding kind plus UTF-16 — negotiation lands on UTF-16, no panic.
- `didChange`: a document whose URI points to a nonexistent file receives a failing incremental edit — the document remains tracked with its last-known text.
- Full battery at cycle end: three feature configurations, `fmt --check`, `clippy --all-targets -- -D warnings` (green), `doc -D warnings`.
- Task order for the implementation plan (all TDD): ① C1-green → ② `error.rs` hard break + rename → ③ walker → ④ encoding → ⑤ `didChange` → ⑥ tracing.
